# ADR-0020: 暦に沿った定期通知と間隔指定

## Status

Accepted (2026-10-04)

## Context

週次だけでなく月次・年次や隔週の通知を、LINEから登録・変更・停止・再開したい。

## Decision

- ADR-0015の通知方式を維持し、daily/weekly/monthly/yearlyと1〜100のintervalを扱う。単発はinterval=1。
- JSTの初回日時を周期の起点とする。月次は指定日、年次は指定月日を別に保存し、存在しない日だけ末日に寄せる。月末は31日指定で表現する。2月29日は平年だけ2月28日とし、うるう年には戻す。
- 次回計算・登録時の整合性検証はdomainの純粋関数。LLMは依頼の解釈だけを行い、通知時に推論しない。
- 初回は未来かつinterval×366日以内。第N曜日・複数曜日・営業日・祝日調整・時間単位は未対応として聞き返す。
- 既存行・状態・版・送信台帳を保持するD1 migrationで拡張する。予定一覧にも間隔と指定月日を表示する。

## Consequences

31日→28日→28日のような日付のずれを避ける。確認文に次回日時と元の指定日を表示し、末日補正をREADMEで説明する。Cron・Queues・Pushの通数は既存方式のまま。

## Enforcement

月末、うるう年、年越し、間隔、停止・再開、変更、旧データ移行をテストする。配備時には旧Workerの列指定なしINSERTと新schemaの互換性に注意し、READMEの移行手順に従う。`pnpm verify`を実行する。
