# ADR-0021: 会話からの予定参照と改善受付

## Status

Accepted (2026-10-04)

## Context

通常会話でDBの予定を知らないまま未登録と回答し、自然な改善依頼も通常回答へ流れていた。

## Decision

- 既存の操作判定に読み取り専用のinspectを追加する。予定・収集日の質問に限り、許可グループの通知と収集設定を読んで回答へ渡す。SQLや送信先をモデルに指定させない。非メンションの自発参加ではinspectだけで返信しない。
- 会話・長期記憶は背景情報、DBは登録予定の正本。予定を長期記憶へ複製せず、取得した結果をその回答だけで利用する。取得失敗を未登録と扱わない。入力予算に合わせた省略を明示する。
- 改善とPR作成を明示する自然文を、メンション時に既存の改善確認へ送る。曖昧な表現は固定コマンドを案内する。実行は引き続きIDと版を指定した明示承認のみ。履歴やDB結果をGitHubへ渡さず、承認した依頼本文だけを送る。
- ADR-0018の変更範囲をapplication/domain/core/bootstrap/infrastructureのTSとunit/integrationテストへ拡張。最大5ファイル、1ファイル30000文字、入力80000文字は維持。入力に全文がないファイルは変更しないよう生成へ指示する。
- Workflow・スクリプト・依存設定・migration・router入口は対象外。publishは生成コードを実行しない。検証ジョブの隔離、Draft PR、人間のマージは維持。

## Consequences

自然文の受付は明確な語句に限定するため取りこぼしは残る。一般的な自律コーディングエージェントではなく、1回の生成で小さな修正を試す仕組みである。読み取り判定もLLMに依存するため、確実な確認には予定一覧を使える。

## Enforcement

自然文で確認のみ作成すること、inspectのパース、予定の正本・省略・識別情報の除外、変更パス制約をテストする。`pnpm verify`を実行する。
