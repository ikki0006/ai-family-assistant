# URL参照と会話の続き

許可された家族グループで使える。既存のTAVILY_API_KEYとGemini接続を使い、追加設定・D1 migrationは不要。

## URLを送る

- URLを一つだけ送ると本文を読み取る。文章にURLを添える場合はメンションするか、botの質問へ返答する。
- お店や公園なら名前・所在地を確認して「ここで合っていますか？」と聞く。記事について質問すれば内容に基づいて答える。
- 「このお店を行きたいお店リストに追加して」なら、特定した店と追加先を確認する。URLだけを送った場合は、場所の確認だけで勝手に登録しない。
- 取得できなければ名前や画像を尋ねる。地図の短縮リンクやログイン必須ページなど、すべてのURLに対応するわけではない。
- 1回1URL。本文は8,000文字まで参照し、検索と共通の月間回数枠を消費する。リンクの取得本文は保存しないが、URLを含むユーザーの発言と最終回答は通常の会話履歴に残る。

## 普通のチャットで返す

「何時に通知しますか？」に「18時」と返すなど、直前の質問に明らかに答えていればメンション・引用なしでも反応する。
同じ人への質問だけを10分間、最大5発言まで判定する。別の人の発言や人への引用返信は対象外。曖昧な発言や判定失敗には反応しないため、その場合はメンション・引用・クイックリプライを使う。
新しい回答を送ったら以前の通常確認ボタンを失効させ、確認待ちを更新する。履歴削除で確認待ちも消える。
改善PR作成やリスト全削除の承認は専用ボタンを使う。

## 検証範囲

ローカルのモックでURL取得・通常返信・質問の失効を検証する。実際のLINE操作、リンクごとの抽出品質、Geminiの判定品質は配備後に確認する。

取得失敗は `page_read_*` の固定コードとHTTPステータスで記録する。認証・上限・タイムアウトはLINEの返答でも区別する。URL・取得本文・APIキーはこの診断ログに含めない。Workersで非対応のredirect:errorは使わず、manualとHTTPステータス検査で転送を拒否する。
