# ADR-0004: 記憶の管理と外部送信を分離する

## Status

Accepted (2026-10-04)

## Context

普段の家族の会話を数日の短期記憶として保存し、その中から重要事項を長期記憶に残したい。
AIプロバイダーや個人情報を加工するAPIは交換できるようにする。
長期記憶を自動削除する条件は、現時点では未決定である。

## Decision

- 短期記憶と長期記憶の保存を、回答に使うコンテキストの選択から分離する。
- AI呼び出しと送信前の個人情報加工を、別のportとして定義する。
- applicationで加工を実行してからAIへ渡す順序を管理する。加工に失敗した場合は未加工の原文で代替しない。
- マスキングだけで任意のAPI利用規約を満たすとはみなさない。送信先の条件と扱うデータに応じて接続を選ぶ。
- 記憶と根拠となった会話の関係を保持する。明示的な削除では、元の会話や処理中のジョブから記憶が再生成される経路も扱う。
- 外部API、LINE側の履歴、バックアップの削除は自アプリのDB削除と区別する。
- 長期記憶の自動忘却、期限の決め方、訂正時の優先順位は後続のADRで決める。

## Consequences

`application/privacy`は送信前処理や削除の手順を持ち、`infrastructure/privacy`は具体的な加工方法を持つ。
これらは設計上の境界であり、この初期構成ではまだ実装しない。
AIプロバイダーは固定せず、課金設定やAPIキーも追加しない。

## Enforcement

層の依存方向を`pnpm check:architecture`で検査する。
機能実装時は、加工失敗時の送信停止、グループ間の分離、削除と実行中ジョブの競合をテストする。
