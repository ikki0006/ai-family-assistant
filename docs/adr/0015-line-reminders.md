# ADR-0015: LINEから通知を管理し5分間隔で実行する

## Status

Accepted (2026-10-04)

## Context

家族がLINEから単発・定期リマインドを登録・変更・停止・再開・削除したい。
メンション以外でも通知に役立つ場面には参加し、botへの引用返信には回答する。
通常のスタンプ連投では保存も推論も行わない。

## Decision

- 第1段階は単発、毎日、毎週の通知。タスクの期限・完了管理、毎月・隔週の繰り返しは後続とする。
- 通知はD1のremindersへ会話と別に保存する。履歴リセットや7日間の記憶期限では削除しない。通知削除はタイトルを消し、再配信防止用のIDと状態を残す。
- LLMは構造化された操作候補を返す。applicationで検証し、保存結果から確認文を生成する。モデルが登録成功を宣言しただけでは登録にならない。
- 一度の依頼では一件だけ操作する。対象が曖昧なら質問する。送信先はサーバーの許可グループに固定し、モデルから指定させない。
- 日時はJST、最初の通知日時は1年以内の未来。日付を省略して既に時刻が過ぎた場合は確認する。通知は通常指定時刻から0〜5分程度遅れ、基盤障害時の定刻到着は保証しない。
- 繰り返し計算はdomain/remindersの純粋関数とし、ADR-0005の将来切り出し条件を満たす最小のdomainを設ける。
- TerraformのCronを */5 * * * * にする。D1のgroup/status/next_at索引で最大50件を取り出し、既存Queueへ本文なしのID・version・日時を送る。予定なしの巡回ではLLMを呼ばない。
- 家族DO内で操作と通知送信を直列化する。送信直前にD1の状態・version・日時を再照合し、古いQueueメッセージを破棄する。ネットワーク送信開始後の取り消しはできない。
- 各通知回で同じLINE retry keyを使う。成功後に送信台帳と次回日時をD1 batchで更新する。失敗時はQueueと次のCronで再試行する。23時間以上古い回は送らず、次の未来の回へ進める。台帳は30日保持。
- botへの引用返信は送信APIのsentMessages.idを記録し、WebhookのquotedMessageIdと照合する。他人同士の引用返信は無条件には割り込まない。対応開始前のbotメッセージや7日を超えた引用、送信応答を失った場合は識別できないためメンションを使う。
- outgoingの本文は短期記憶と同じ7日保持。送信取消時には派生情報として全消去、履歴リセットでも消去する。
- 非メンションの参加は期限・予定関連の語句で候補を絞り、通常候補の推論は最短1分間隔にする。AIがnoneなら沈黙。自発的な提案は最短30分間隔。候補判定には取りこぼしがあるため確実な操作にはメンションまたはbotへのリプライを使う。
- 非メンションでは明確な通知依頼の文言がない操作候補を、保存を伴わない確認質問へ変換する。会話内の予定を勝手に登録しない。明確な依頼にはメンションなしでも登録する。
- スタンプはquotedMessageIdやメンションがあっても入口で無視する。画像等も現在は対象外。
- 全推論は既存の予算制限Gateway経由。操作判定は最大30秒、回答と合わせて120秒。通知実行時は推論不要。非メンション参加により推論回数が増える。
- 既存のゴミ出しは収集日計算・送信台帳を維持する。Cron変更後も23時/8時と再試行枠だけ実際に送る。ゴミ出し設定の会話からの変更は対象外。

## Consequences

5分間隔で簡素なスケジューラを維持する。通知と会話の寿命を分離できる。
操作の自然言語解釈はモデル依存であり、日時と内容を登録結果で明示する。
一覧は最大100件、回答はLINE側の文字数予算に従い省略され得る。
既存Queueの生成重複防止のため、確認回答の配信失敗後も登録だけ完了している場合がある。一覧で状態を確認できる。
LINEのPush通数は通知のたびに消費する。AI利用料とは別枠である。

## Enforcement

純粋関数で日付・繰り返しと不正な操作候補を検証する。
Workers/D1テストで重複登録、状態変更、古いジョブ、再送キー、次回更新、グループ分離を検証する。
Webhookテストで引用ID保持とスタンプ連投の無視を検証する。
`pnpm verify`を実行し、本番ではD1 migration後にアプリを配備してからTerraformのCronを更新する。
