# ADR-0019: 回答と記憶整理を分離し長期記憶をD1へ保存する

## Status

Accepted (2026-10-04)

ADR-0014の回答前要約と長期記憶・削除範囲を更新する。

## Context

回答前の要約は応答を遅らせる。通常会話から継続的な事実を残し、家族が保存内容を確認・訂正・削除できる必要がある。

## Decision

- 回答と記憶整理を分離する。既存CronとQueueで整理し、回答は保存済みの要約と記憶を参照する。
- 整理専用のGemini呼び出しで短期要約と長期記憶候補を同時に生成する。既存Gatewayの予算を共有する。
- 原文・要約は家族DO、長期記憶はD1に保存する。事実には根拠のユーザー発言IDと有効期限を持たせる。
- LLMは候補を提案し、アプリが根拠・形式・削除世代を検証して保存する。送信取消や削除と競合した結果を採用しない。
- 記憶・予定の一覧と明示的な保存・削除はDBから直接処理する。予定と会話の寿命は分ける。
- 新たなモデル契約、ベクトルDB、Queueは追加しない。関連記憶の取得は簡易キーワード順位から始める。

実行間隔、容量、リース、コマンド、削除の詳細は[記憶の処理仕様](../memory.md)にまとめる。

## Consequences

回答は整理を待たなくなる。自動抽出には遅延と取りこぼしがあり、直近の会話を併用する。
D1とDOの更新は分散トランザクションではないため、再実行可能な更新と永続化した削除要求で回復する。
原文の自然失効では長期記憶を消さない。明示的な全消去では会話・要約・長期記憶を消し、通知は残す。

## Enforcement

単体テストで根拠検査・一覧・入力予算を、Workers/D1統合テストで家族分離・重複・期限・整理中削除を検証する。
配備前に`pnpm verify`を実行し、D1 migration 0005をアプリより先に適用する。
