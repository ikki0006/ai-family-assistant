# ADR-0028: 担当者別・周期別に完了を管理するタスク

## Status

Accepted (2026-10-13)

## Context

毎月の振込など、複数人がそれぞれ完了し、未完了の人にだけ毎日通知する必要がある。通常のリマインダーは送信時に次回へ進むため、完了管理を追加すると意味が混ざる。

## Decision

- タスク定義と担当者・周期ごとの実行分をD1の専用状態として保存する。会話・記憶・共有リスト・既存リマインダーから独立させる。履歴リセットでは消えない。
- domain/tasksが周期分の生成と毎日の通知枠を計算する。日次・週次・月次・年次・間隔・月末補正は既存domain/remindersを再利用する。
- 担当者は確定済みプロフィールの名前とLINE userIdから解決する。本人指定は受信話者を使える。曖昧な名前・不明な時刻は確認し、勝手に割り当てない。
- 既存5分Cron/Queues/家族DOを利用する。DOの排他区間で未完了を再確認し、タスクごとに家族グループへまとめてPushする。初回日時から毎日同時刻、通常0〜5分程度の遅れ。通知生成にLLMは使わない。
- 完了は本人の自然文（メンション・bot引用返信）または本人専用postbackから受け付ける。対象の期限が複数なら確認する。ボタンは周期IDに固定し、他人の完了や次月への流用を防ぐ。
- 同じ回の一人が完了しても他の人は未完了のまま。次の周期には新しい実行分を生成し、前月の未完了も保持する。停止・再開は未完了を残し、削除は定義と実行分を削除する。
- D1のversionとイベントIDで比較更新・重複排除する。Pushの再試行キーはタスクと日ごとに固定。各タスク20件以下・担当者6人以下、実行分は1タスク最大1000件。周期生成の巡回時に90日超の完了済みを整理し、滞留した周期は1巡回30周期ずつ追いつく。上限時は新規周期生成を保留し、既存未完了の通知は続ける。

## Consequences

0009_family_tasks.sqlの適用が必要。追加サービス・Secrets不要。個別DM、代理完了、周期・担当者の直接編集は初版対象外。変更は停止/削除と新規登録で行う。Push通数は通常通知と同じ枠を使う。

## Enforcement

担当者の分離、期限ごとの完了、月をまたぐ未完了、日次重複防止、失敗時再送、停止・再開・削除、D1競合、Cron/Queue/自然文/postback接続を検証する。実LINE送信はテストで行わずpnpm verifyを実行する。
