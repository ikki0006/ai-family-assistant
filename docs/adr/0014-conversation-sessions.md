# ADR-0014: Sessionsで短期会話を保存し回答へ渡す

## Status

Accepted (2026-10-04)

## Context

通常の家族の発言も保存し、メンションされたときだけ文脈付きで回答する。
合意した初期範囲は7日間の短期記憶、必要時の要約、削除であり、長期記憶の抽出は後続とする。

## Decision

- 家族グループごとにSQLite Durable Objectを1つ作り、日本時間の日付ごとにAgents Sessionsを分ける。
- agents 0.26.0の`agents/sessions`と`agents/lifecycle`を利用する。Experimental APIの利用はinfrastructureとbootstrapへ閉じ込める。
- SDKは会話原文を保持する。アプリのRepositoryが時刻・イベントID・削除世代・日別要約を同じSQLiteで管理する。D1に会話原文を二重保存しない。
- 会話型は`application/conversation/conversation.ts`、秘書と要約の指示は`application/prompts`に置く。portsとinfrastructureから会話モデルの型参照を許可する。
- 署名・許可グループを検査してから通常のテキスト発言も保存する。話者はLINE user IDで区別し、プロフィール取得はしない。
- Queueには本文ではなくmessage IDと世代番号を渡す。reply tokenはQueueにのみ含める。旧形式の待機ジョブは記憶導入後には生成せず破棄する。
- 回答時は質問の時刻以前の直近300件を候補にする。同時刻では質問を最後に置き、後から届いた古い発言は要約と処理中の回答を無効化する。
- 5,000 UTF-8 bytesを超える候補では、直近3発言を残し、古い日付から1回だけ要約する。要約入力は12,000 bytes、結果は3,200 bytes以下。毎時のLLM呼び出しは行わない。
- 回答入力はsystemとメッセージを合わせて保守的な8,000 bytesの予算に収める。SDKの英語寄りトークン推定に頼らず、日本語もUTF-8で数える。約8,000トークンという計画より保守的な制限とする。
- 要約失敗・予算到達時は保存済み要約と直近履歴へ縮退する。要約は20秒、回答と合わせて生成待ちは最大120秒。すべて同じGatewayを使う。
- 保存から7日を超えた原文は受信・参照時と1時間ごとのDO alarmで削除する。期限切れ・送信取消時は派生要約を無効化し、取り消した原文から派生し得るbot回答も取り除く。
- bot宛ての『履歴リセット』で原文と要約を削除し、世代番号と時刻の境界で待機ジョブ・古い再配信を無効化する。本文なしの取消IDとリセットIDは8日間保持する。
- LLM待ち中は削除を受け付ける。送信直前に世代と改訂番号を検査し、削除と競合した回答は送らない。送信開始後の取り消しはLINEへ遡及できない。
- LINE送信成功後の回答だけを履歴に保存する。送信とSQLite更新は分散トランザクションではなく、送信後の障害では回答履歴が欠落し得る。既存の重複生成防止を優先する。
- DOクラスのSQLite migrationとbindingはアプリのバージョンと不可分なのでwrangler.jsoncとWorkers Buildsで配備する。Worker本体、D1、Queues、Gateway、Cronは引き続きTerraformが管理する。

## Consequences

保存期間とモデルに渡す文脈を分離する。保存した全会話を毎回モデルへ渡すわけではない。
要約はアプリが日別に管理し、SDK標準の非破壊compactionに削除を委ねない。
画像・添付ファイル、長期記憶、自動予定登録、任意の通知設定は対象外。
会話と要約は平文でDOのSQLiteに保存される。プロンプト本文をアプリログやGatewayへ記録しない。
アプリ内の削除は、LINEの履歴・プロバイダー側・Cloudflareのバックアップ削除を保証しない。

## Enforcement

単体テストで通常発言の保存と返信判定の分離、入力上限、要約失敗時の縮退を検査する。
実WorkersランタイムのSessions/SQLiteで永続化、重複、期限、グループ分離、送信取消、世代無効化、生成中削除を検査する。
`pnpm verify`で型、依存方向、テスト、ビルドを検証する。
