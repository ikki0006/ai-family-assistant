# ADR-0022: 本人が確認した家族プロフィール

## Status

Accepted (2026-10-04)

## Context

発言者IDは保存しているが、名前・呼び名との対応がない。対応表をGitへ保存せず、会話から整理し、通常の長期記憶とは異なる寿命で扱いたい。

## Decision

- D1 family_profilesにグループ・話者ID・確定名・確認待ち候補・根拠発言ID・版を保存する。最大10人、名前と呼び名は各20文字で3個まで。
- 既存の非同期整理LLMが本人の自己紹介から候補を抽出する。候補の話者と元の発言者が一致し、名前が原文にあることを検証する。推測の誤確定を避け、LLM候補は本人の版付き承認後に確定する。明示登録コマンドは本人の意思として即時確定する。
- 回答・通知判定・記憶整理に毎回プロフィールを渡す。名前の同一性を権限判定には使わない。確認待ちの呼び名を確定扱いせず、同名は聞き返す。
- 自動失効しない。履歴リセット・通常の記憶全消去では残す。本人分の削除と、記憶・プロフィールを合わせた全消去を別に用意する。通知と収集設定は全消去の対象外であることを返答する。
- 元発言の取消ではプロフィールも削除する。明示削除は根拠発言も消し、整理中の古い結果を無効化する。全消去はDO outboxでD1削除を回収する。
- 確定より古い発言からの候補は採用しない。抽出は確認待ちだけを書き換え、確定情報を上書きしない。

## Consequences

LLMの意味判断と本人確認を分けるため確認操作が増える。候補抽出は通常の記憶整理のタイミングで行い、即時とは限らない。名前は個人情報としてDBに保存し、家族の回答生成時に既存Gateway経由でモデルへ渡す。

## Enforcement

migration 0007を先に適用する。根拠・話者の検証、グループ分離、版、訂正後の古い候補、削除をテストする。操作方法は[家族プロフィール](../profiles.md)。
