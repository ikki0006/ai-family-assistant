# 家族の共有リスト

リマインド・会話記憶とは別に、リスト名と項目・メモをD1に保存する。家族グループで共有し、メンションまたはbotへの引用返信で操作する。

- 「行きたいお店リストを作って」
- 「行ってみたいお店に架空カフェを追加して。メモはテラス席」
- 「行きたい公園リストを見せて」「続きも見せて」
- 「架空カフェのメモを昼営業に変更して」
- 「架空公園をリストから外して」
- 「公園リストを家族で行きたい公園に名前変更して」
- 「今あるリストを教えて」「お店リストを削除して」

「行きたいお店」「行ってみたいお店」などの意味が同じ表現は既存リストを使う。曖昧な対象は質問と選択肢で確認する。意味判断はLLM、明白な表記ゆれ・重複はアプリ側でもチェックする。改名後の旧名は最大5個残す。別リスト同士を自動で合体しない。

リスト全体の削除は項目も消えるため、質問した本人に確認ボタンを出す。確認後にリストが更新された場合は削除せず再確認する。項目単体の明示的な削除はそのまま反映する。

リスト20個、1リスト50項目、全体200項目まで。名前40文字・項目名100文字・メモ300文字。内容は4件ずつ表示する。現在の登録内容をDBから読み、会話の要約を一覧の代わりにはしない。

会話履歴・長期記憶・プロフィールの消去ではリストは残る。リストの情報を消したい場合はリスト側で削除する。削除しても元のLINEメッセージや会話履歴は別途残る。再実行防止のイベントIDは本文なしで保持する。

本番利用には `0008_family_lists.sql` の適用後、Workerを配備する。通知用CronやQueueは追加しない。
