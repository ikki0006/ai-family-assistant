# 家族プロフィール

D1にLINE話者IDと名前・呼び名を保存する。実際の対応表はコードやGitに置かない。
回答・通知判定・非同期記憶整理へ毎回渡し、一般の長期記憶の関連度検索とは分ける。

## 登録・訂正

会話中の自己紹介を既存の非同期整理が候補として抽出する。本人の発言だけを根拠とし、他人への呼びかけから話者を推測して確定しない。抽出完了まで通常の整理待ち時間がある。

メンションまたはbotへの引用返信で操作する。

- `プロフィール一覧`：確定済みと確認待ちを表示する。
- `プロフィール承認 2`：本人の確認待ち候補の版を指定して確定する。他人のプロフィールは承認できない。
- `プロフィール登録: テスト太郎、たろう`：本人の名前・呼び名を即時登録・訂正する。以前の呼び名は置き換える。例は架空。
- `プロフィール削除`：本人のプロフィール、根拠発言と派生情報を削除する。
- `記憶・プロフィール全消去`：家族の会話・要約・長期記憶・プロフィールを削除する。通知・収集設定とLINE上のメッセージは残す。

名前・呼び名は各20文字、最大3個。家族プロフィールは最大10人。確認待ち候補を返答の呼び名として断定せず、同名のメンバーが複数いる場合は確認する。
通常の`履歴リセット`・`記憶全消去`ではプロフィールを残す。自動期限切れもない。元の自己紹介を送信取消した場合は、その発言を根拠に持つプロフィールを削除する。

初回配備には`0007_family_profiles.sql`を先に適用する。プロフィールは家族全員から確認でき、既存のAI Gatewayを通じてモデルへ渡される。名前は認証や権限判定には使わない。
