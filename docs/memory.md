# 会話・記憶の処理仕様

採用理由は[ADR-0019](adr/0019-background-memory.md)、LINEの操作方法は[README](../README.md#短期会話と秘書プロンプト)を参照する。

## 実行・保存・削除

- 回答は保存済み要約・直近履歴・関連する長期記憶を読むだけで、整理の完了を待たない。
- 既存の5分Cronが家族DOへ確認する。未処理の発言があり、最終発言から15分静か、または最古の未処理発言が1時間前なら、既存Queueへ本文なしのmemoryジョブを送る。少なくともCron・Queueの待ち時間が加わる。滞留時には複数回に分けるため全件整理を1時間以内に保証しない。
- Queueは既存のbatch_size=1、max_concurrency=2を維持する。家族ごとの15分リースとDO内の実行中フラグで整理を直列化。推論中は会話ロックを解放する。失敗時はQueue再試行、リース切れ後は次のCronで回収する。
- Geminiを整理専用プロンプトで最大60秒呼び出す。回答と同じGateway予算を使う。新しいモデル契約・インフラは増やさない。会話がなければ推論しない。
- 日別の未処理原文を最大100件・おおむね12,000 UTF-8 bytesまで取得し、既存要約と関連する長期記憶を渡す。同一時刻の一部だけを要約済みにしない。根拠がある長期記憶候補と短期要約を同時に生成する。
- 個別事実はD1のlong_term_memoriesでgroup/subject/key、本文、元発言ID、有効期限、更新時刻を保持する。最大200件、本文各300文字。更新は同一キーのupsert。抽出は意味的な判断なので完全性は保証しない。
- AI回答・検索結果は家族の事実の根拠にしない。ユーザー発言IDと話者・期限・サイズをコードで検証する。推測や曖昧な情報は長期保存せず短期要約にとどめる。期限切れの事実は参照・巡回時にSQLで削除する。
- 整理結果の反映時に世代・改訂・リースを再検査。D1更新後にDOの処理済みIDを保存する。途中障害時は同じsubject/keyのupsertで再実行を許容する。D1とDOは分散トランザクションではない。
- 原文は7日で削除するが、長期記憶は原文の自然失効では消さない。送信取消では該当発言を根拠に持つ事実も削除する。削除要求はDOのoutboxへ先に記録し、次の参照前にD1へ反映する。
- 記憶削除IDは根拠となった原文と、同じ根拠を持つ事実、関連し得る全bot回答・要約を消す。再抽出による復活を防ぐため削除世代と取消IDを利用する。元発言の独立した言い換え等までは自動追跡できない。
- 記憶全消去と履歴リセットは会話・要約・長期記憶を消す。D1の通知は残す。
- メンション/引用返信の「記憶一覧」「何を覚えてる？」「予定一覧」を直接解釈し、LLMなしでDBから返す。長期記憶は4件、予定は4項目ずつページング。予定には通常通知の状態とゴミ収集ルール・例外・設定有効期間を含める。
- 明示的な即時保存は「覚えて: 内容」、個別削除は「記憶削除 ID」。自由文による曖昧な削除は実行しない。上限時は明示する。
- 回答への記憶検索は二文字の部分一致と更新時刻による簡易順位。上位8件から1,800 bytesまでを選び、既存8,000 bytes入力予算内に含める。ベクトル検索は導入しない。


## 配備

D1 migration 0005を先に適用し、Workerを配備する。新しいSecretやTerraformリソースは不要。
推論の抽出精度と関連度は本番試用で確認する。原文の自然失効とユーザーによる削除は別の操作として扱う。
