# ADR-0024: 文脈からの改善提案と生成コンテキストの選択

## Status

Accepted (2026-10-06)

## Context

語句の正規表現では「それ作れる？」などの改善依頼を拾えなかった。Actionsの生成失敗も、空の結果・JSON不正・出力上限・変更範囲違反が一つのエラーにまとめられ、原因を識別できなかった。ソースを固定順で上限まで渡すため、依頼に必要なファイルが欠ける。

## Decision

- ADR-0021の自然文受付を、既存の会話操作LLMによるimprove判定に置き換える。最新発言と直近履歴・引用から変更内容を提案する。生活相談・既存通知操作・否定は区別する。非メンションの自発参加では改善を提案しない。
- 固定コマンドは互換用に残すが要求しない。会話から作る仕様は最大1500文字、個人情報を一般化し、送信予定の仕様を表示して承認を得る。LLMは承認・Actions起動を選べない。ボタンのID・版照合と原子的claimは維持。
- Actionsは許可されたファイル一覧からモデルが1〜12個を選び、全文を合計80000文字以内で渡す。超過は黙って省略せず停止する。
- 実装生成は一致箇所が一つだけの文字列置換を使う。既存ファイル全文の再出力を避け、未提示ファイルへの変更は拒否する。最大5ファイル・各30000文字・既存の変更パス制限・隔離検証・Draft PRを維持。
- 呼び出しは選択1回、生成1回。同じ予算管理Gatewayを通し、エラーで自動再試行しない。失敗理由を区別するが生成本文・秘密値をログへ出さない。

## Consequences

受付はモデル判断に依存する。確認と承認を分け、誤提案をキャンセルできる。生成の成功は保証せず、DB migrationや変更範囲外の作業は依然扱えない。過去の一括エラーログから詳細な失敗理由は復元できない。

## Enforcement

文脈付き提案から確認ボタンへの接続、自発参加時の拒否、提案だけではdispatchしないこと、ソース選択制限・正確な置換・失敗理由を検証する。pnpm verifyを実行する。
